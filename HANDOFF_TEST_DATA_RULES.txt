Rule Test Scenarios
-------------------

R-L-001 - Search requires at least one criterion
UI:
  1. Open /loans/search.
  2. Leave Loan number and Borrower name blank.
  3. Click Search.
Expected:
  Enter at least one search value before searching.

Swagger:
  GET /api/loans/search
  Do not provide LoanNum, BorrowerName, or PropertyAddress.
Expected:
  400 Bad Request with ApiErrorDto.


R-L-002 - Loan number must be exactly 10 numeric digits
UI:
  1. Search with Loan number: 12345
Expected:
  UI validation blocks the search.

Swagger:
  GET /api/loans/search?LoanNum=12345
Expected:
  400 Bad Request with a rule-linked loan number error.


R-L-003 - Quote requires an approved property state
UI:
  1. Search Loan number: 4444444444
  2. Select the result.
  3. Click Process selected loan.
Expected:
  Quote is not available for this property state.

Swagger:
  POST /api/quotes/loan/4444444444
Expected:
  400 Bad Request with ApiErrorDto.


R-L-004 - Kentucky quote requires ISO pre-call
UI:
  1. Search Loan number: 1234567890
  2. Select the result.
  3. Click Process selected loan.
Expected:
  Process completes. KY ISO advisory lookup is called before quote generation.

Swagger:
  POST /api/quotes/loan/1234567890
Expected:
  200 OK with QuoteResultDto.


R-L-005 - Quote generation only when QuoteReqd = Y
UI:
  1. Search Loan number: 3333333333
  2. Click Process selected loan.
Expected:
  Quote is skipped because QuoteReqd = N; EDI can still dispatch because EdiFlag = Y.

Swagger:
  POST /api/quotes/loan/3333333333
Expected:
  200 OK with QuoteResultDto amount of 0.


R-L-006 - 14E notifications require EDI enrollment
UI:
  1. Search Loan number: 2234567890
  2. Click Process selected loan.
Expected:
  No EDI dispatch occurs from ProcessLoanResult because EdiFlag = N.

Swagger:
  POST /api/edi/notifications/14e
  Body:
    {
      "loanNumber": "2234567890",
      "formId": "LT-F200"
    }
Expected:
  400 Bad Request: loan is not enrolled for EDI.


R-L-007 - Instant Issue suppresses 14E
UI:
  1. Search Loan number: 5555555555
  2. Click Process selected loan.
Expected:
  Instant Issue cycle suppresses 14E dispatch.

Swagger:
  POST /api/edi/notifications/14e
  Body:
    {
      "loanNumber": "5555555555",
      "formId": "LT-F200"
    }
Expected:
  400 Bad Request: Instant Issue suppresses 14E dispatch.

R-L-014 - Modify enforces governed updates
UI:
  1. Search Loan number: 1234567890.
  2. Click Modify loan.
  3. Try to save Loan status: CLOSED while current status is ACTIVE.
  4. Or increase UPB above 200000.
Expected:
  400 Bad Request: update violates modification rules.

Swagger:
  PUT /api/loans/1234567890
  Body:
    {
      "loanNum": "1234567890",
      "borrowerName": "Jordan Smith",
      "propertyAddress": "120 Main St",
      "loanStatus": "CLOSED",
      "unpaidPrincipalBalance": 210000,
      "propertyValue": 250000
    }
Expected:
  400 Bad Request.

Valid modify example:
  PUT /api/loans/1234567890
  Body:
    {
      "loanNum": "1234567890",
      "borrowerName": "Jordan Smith",
      "propertyAddress": "120 Main St Updated",
      "loanStatus": "DELINQUENT",
      "unpaidPrincipalBalance": 190000,
      "propertyValue": 250000
    }
Expected:
  200 OK with LoanMutationResultDto.

Notes For UI Teams
------------------
These are the public UI-facing endpoints exposed by the Presentation layer:
  GET  /api/loans/search
  POST /api/loans
  PUT  /api/loans/{loanNumber}
  POST /api/quotes/loan/{loanNumber}
  POST /api/edi/notifications/14e

The Application command/query handlers are internal backend services and are not separate HTTP endpoints.
