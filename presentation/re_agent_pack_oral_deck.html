What the Blueprint contains (Part 1–4)
  • TypeScript interfaces for all UI models
  • C# .NET Core controller stubs with method signatures
  • SQL DDL migration scripts for Azure SQL target
  • xUnit test scaffolds for all Priority-stamped rules
  • DDD layer structure — Domain / Application / Infrastructure / Presentation with dependency rule enforced (Domain → nothing; Application → Domain; Infrastructure → Domain + Application)
Why the DGT taxonomy format?
  • The DGT tool reads it directly to generate .NET controller layer
  • Paste into Claude / ChatGPT → complete API layer in one shot
  • Business rules from BRD link back to each API operation
  • Full 18-column format includes validation rules, error codes, test refs
Governance

Human-in-the-Loop — Mandatory Review

AI cannot be taken as-is. Every generated document goes through business, architecture, and lead review before forward engineering begins.

AI Output — What the pipeline generates

  • 25 business rule cards — each with Plain-English + technical statement
  • Grounding labels on every claim — [code-grounded], [inferred], [placeholder]
  • Review Priority stamps — Priority (high risk) vs Standard (low risk)
  • Ambiguity log — open items flagged for SME resolution
  • Publication readiness gate — Step 8 blocks Go if any [placeholder] appears unqualified
"For AI, we definitely can put that message — it cannot be pitch perfect. Human loop is definitely required."

Review Workflow — What the team does

  • Business team validates the generated Word documents — not the repo
  • Architecture review confirms Tandem integration flows are accurate
  • Tech leads review business rules register (Review Priority guides reading order)
  • Sign-off → documents sent to modernisation team
  • Selective code generation — only after review consensus
"Once the RE docs are created, they are consumed by the team to validate, to review with business, with architects, with leads — that yes, this has covered all the ground."
🛡️
Four Built-in Completeness Safeguards
1. Coverage Gap Scan
rule-extractor checks every function for validate/check/enforce/require/block keywords; flags any function with no rule card.
2. Rule Count Sanity Check
Warns if extracted count < 70% of expected minimum for the file layer.
3. Evidence Reference Verification
Every file::function citation verified; downgrades to unresolved if not found in source.
4. Placeholder Propagation Block
publication-reviewer reads Publication_Contract.json; fails Go/No-go if any placeholder appears unqualified in a final document.
